## Executive Summary

Shardeum is an EVM-compatible Layer 1 blockchain that launched its mainnet in May 2025, followed by a full EVM mainnet upgrade on October 30, 2025. The platform underwent a significant 1:240 token redenomination between October 28-30, 2025, transitioning from 249 million to approximately 59.7 billion SHM tokens. This analysis examines Shardeum's technology, the token conversion event, and its strategic pipeline for scaling blockchain adoption, particularly in India.

**Key Highlights:**
- **Token Redenomination:** 1:240 split (October 28-30, 2025)
- **Current Supply:** 59.7 billion SHM tokens (post-split)
- **Consensus:** Proof-of-Quorum (PoQ) with Proof-of-Stake
- **Scalability:** Linear scaling (~1 TPS per validator node)
- **Target Market:** India-first strategy for global Web3 adoption
- **Exchange Support:** KuCoin, MEXC, LBank, Bitget

## 1. The 1:240 Token Redenomination Event

### 1.1 Overview

On October 6-8, 2025, the Shardeum community voted with 85% approval to redenominate the SHM token supply from 249 million to approximately 59.7 billion tokens at a 1:240 ratio. This was **not an inflationary event**—no new value was created, and existing token holders maintained proportional ownership.

**Source:** [Shardeum Blog - Vote Now: SHM Redenomination Proposal](https://shardeum.org/blog/vote-shm-redenomination-proposal/)

**Source:** [Shardeum Blog - EVM Mainnet Launch & SHM Announcement](https://shardeum.org/blog/evm-mainnet-launch-shm-announcement/)

### 1.3 Impact on Token Holders

**Example:**
- **Before:** 100 SHM = $5 total value
- **After:** 24,000 SHM = $5 total value (subject to market fluctuations)

**Key Points:**
- All balances automatically updated—no user action required
- Staked tokens and uncollected rewards redenominated at 1:240
- Market capitalization remained constant at the moment of conversion
- Price per token decreased proportionally (divided by 240)

**Source:** [Shardeum Blog - Token Split Announcement](https://shardeum.org/blog/evm-mainnet-launch-shm-announcement/)

The redenomination aimed to:
1. **Improve Accessibility:** Lower per-token price for retail investors in emerging markets
2. **Psychological Pricing:** Make token prices more appealing ($0.003 vs $0.72)

## 2. Technology & Architecture

### 2.1 Core Technology Stack

**Blockchain Type:** Layer 1, EVM-Compatible, Dynamically State-Sharded Smart Contract Platform

**Consensus Mechanism:** Proof-of-Quorum (PoQ) with Proof-of-Stake (PoS) Sybil deterrence

**Key Features:**
- Dynamic state sharding with linear scalability
- Blockless, leaderless consensus architecture
- Transaction-level consensus (first-come-first-served)
- Atomic cross-shard composability
- Auto-scaling based on network demand

**Source:** [Shardeum Technical Whitepaper](https://docs.shardeum.org/docs/whitepaper)

### 2.2 Network Specifications

| Parameter | Specification |
|-----------|---------------|
| **Minimum Validators** | 1,300 at mainnet launch |
| **Archiver Nodes** | 10 minimum |
| **Nodes per Shard** | 128 |
| **Token Decimals** | 18 |
| **Current Supply** | 59.7 billion SHM (post-redenomination) |
| **Consensus Finality** | Low-latency (seconds) |
| **Transaction Processing** | ~1 TPS per validator node |

**Source:** [Shardeum Whitepaper](https://docs.shardeum.org/docs/whitepaper)

### 2.3 Scalability Analysis

**Linear Scaling Model:**
- 100 nodes = ~100 TPS
- 1,000 nodes = ~1,000 TPS
- 800,000 nodes = ~62,000 TPS (theoretical with Ethereum-scale validators)

**Dynamic State Sharding:**
Shardeum splits the network into multiple shards that process transactions in parallel. Unlike traditional blockchains that process sequentially, Shardeum handles transactions concurrently, enabling significantly higher throughput while maintaining low latency and fees.

**Source:** [Shardeum Blog - Solving the Blockchain Trilemma](https://shardeum.org/blog/shardeum-solves-blockchain-trilemma/)

### 2.4 Node Architecture

**Validator Nodes:**
- Process transactions and hold state data
- Require 2,400 SHM stake (post-redenomination)
- Earn 10 SHM/hour when active
- Rotated every 60 seconds between active and standby

**Archiver Nodes:**
- Store complete network history
- Critical for data availability and historical queries

**Standby Nodes:**
- Wait in queue for rotation into active set
- Do not earn rewards while in standby status

**Connector/Relayer Nodes:**
- Facilitate cross-shard data movement
- Enable atomic composability

**Source:** [Shardeum Whitepaper](https://docs.shardeum.org/docs/whitepaper) & [Node Staking Documentation](https://docs.shardeum.org/docs/ecosystem/advanced-operations/staking-and-unstaking)

### 3.2 Dynamic Supply Model

**Post-Mainnet Token Issuance:**
- New SHM tokens minted **only for validator node rewards**
- Issuance based on network security needs and staking participation
- No fixed maximum supply—dynamically responsive to network growth

**Deflationary Mechanisms:**
1. **100% Fee Burning:** All transaction fees are permanently burned (not distributed to validators)
2. **Slashing Burns:** Tokens from slashed validators are burned, not redistributed
3. **Demand-Based Issuance:** Validator rewards adjust based on participation rates

**Source:** [Shardeum Whitepaper V2 - Tokenomics Update](https://shardeum.org/blog/whitepaper-tokenomics-update/)

### 3.3 Validator Economics

**Staking Requirements:**
- **Minimum Stake:** 2,400 SHM per validator node
- **Reward Rate:** 10 SHM/hour when active (subject to periodic adjustments)
- **Standby Rewards:** None (only active validators earn)
- **Reward Claiming:** Manual unstake transaction required

**Active vs. Standby Rotation:**
- Network rotates oldest active validators to standby every 60 seconds
- Standby nodes selected randomly (not FCFS) for activation
- Standby-to-Active (S:A) ratio impacts validator profitability

**Source:** [Shardeum Validator Staking Documentation](https://docs.shardeum.org/docs/ecosystem/advanced-operations/staking-and-unstaking) & Search Results on Validator Rewards

### 3.4 SHM Token Utilities

1. **Transaction Fees:** Pay for gas on the network
2. **Validator Staking:** Required for running validator nodes
3. **Governance:** Voting on protocol upgrades (demonstrated in redenomination vote)
4. **Network Security:** Economic security through staking
5. **P2P Transfers:** Native currency for value transfer
6. **Smart Contract Execution:** Required for dApp interactions

## Appendix A: Glossary

**Dynamic State Sharding:** A technique where the blockchain network is divided into multiple shards that can process transactions in parallel, with shards automatically added as validator nodes join.

**Proof-of-Quorum (PoQ):** Shardeum's consensus mechanism where transactions are validated individually on a first-come-first-served basis by a quorum of nodes.

**EVM Compatibility:** The ability to run Ethereum smart contracts without modification using the Ethereum Virtual Machine.

**Linear Scalability:** Network throughput increases proportionally with the number of validators (1 TPS per validator node).

**Token Redenomination:** A process that changes the total supply and per-token price proportionally, maintaining total market capitalization (not a stock split in traditional finance terms, as crypto tokens don't represent equity).

**TVL (Total Value Locked):** The total value of assets staked or locked in DeFi protocols on a blockchain, measured in USD.

**Layer 1 (L1):** The base blockchain protocol layer that processes and finalizes transactions (as opposed to Layer 2 scaling solutions built on top).

**Deflationary Tokenomics:** Economic model where token supply decreases over time through burning mechanisms, creating supply-side scarcity.
